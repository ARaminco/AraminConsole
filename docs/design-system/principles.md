# اصول طراحی

خلاصهٔ جهت بصری مصوب (`docs/DESIGN.md`)، به‌همراه اصولی که از رفتار واقعی کد درمی‌آید.

## ۱. هوا و سکوت
پس‌زمینه یک بوم روشن و آرام است؛ کارت‌ها سفید با **خط مویی** و تقریباً بدون سایه. کار را فاصله و مرز انجام می‌دهد، نه سایهٔ سنگین. هر جا خواستید تمایز بدهید، اول فاصله و تیپوگرافی، بعد مرز، آخر سایه.

## ۲. رنگ کم، معنی زیاد
بیشتر رابط **جوهر + خاکستری + سفید** است. رنگ برند (`--ac-accent`) فقط برای نقطهٔ تأکید: فوکوس، سوییچ روشن، میلهٔ پیشرفت، یک نمودار برجسته. رنگ گرمِ `--ac-highlight` فقط برای یک لکه (شمارندهٔ اعلان). اگر سه رنگ پررنگ در یک صفحه دیدید، دوباره فکر کنید.

## ۳. دکمهٔ اصلی «جوهر» است
دکمهٔ اصلی و پیل فعال ناوبری با `--ac-ink` می‌آیند (مشکی/سرمه‌ای در روشن، سفید در تیره). در هر صفحه **یک** عمل اصلی.

## ۴. راست‌به‌چپ از پایه
طرح اول برای فارسی ساخته می‌شود و بعد در انگلیسی آینه می‌شود، نه برعکس. ریل کنار راست است، فلش‌ها وارونه می‌شوند، نمودار از راست شروع می‌شود. ← [rtl-i18n.md](rtl-i18n.md)

## ۵. اپلیکیشن‌گونه روی گوشی
زیر ۶۴۰ پیکسل: تب‌بار شناور پایین، شیت‌های کشویی، کشیدن برای تازه‌سازی، هدف لمسی حداقل ۴۴ پیکسل، ناحیهٔ امن. گوشی نسخهٔ کوچک‌شدهٔ دسکتاپ نیست. ← [patterns.md](patterns.md)

## ۶. حرکت هدفمند
حرکت یعنی توضیحِ تغییر، نه تزئین. سریع (زیر ۳۰۰ms)، قابل قطع، فقط `transform` و `opacity`. هرچه روزی صدبار استفاده می‌شود (کیبورد، پالت) بدون انیمیشن است. ← [motion.md](motion.md)

## ۷. توکن‌محور
کامپوننت‌ها فقط توکن می‌خوانند. تم تیره، پریست برند، تراکم فشرده و شعاع گرد بدون یک خط CSS اضافه کار می‌کنند. اگر برای حالت تیره مجبور شدید `:root[data-theme="dark"] .my-thing` بنویسید، احتمالاً یک توکن کم است.

## ۸. دسترس‌پذیری پیش‌فرض است
کنتراست WCAG 2.x، حلقهٔ فوکوس، کیبورد، `aria-*` و کاهش حرکت جزو خود کامپوننت‌هاست، نه افزونه. ← [accessibility.md](accessibility.md)

## ۹. همان‌چه هست را بازاستفاده کنید
قبل از ساخت چیز تازه: کلاس‌ها و `data-ac`‌های موجود ← [components.md](components.md). ساخت کامپوننت جدید فقط وقتی که هیچ‌کدام جواب نمی‌دهد، و آن هم با توکن‌ها.
